Lesson 8: Accessibility

Goal: Check a page for readable content, useful labels and keyboard access.

Accessibility means people can use the page in different ways. Someone might enlarge text, use a keyboard instead of a mouse, or listen with a screen reader.

What is WCAG?

WCAG stands for Web Content Accessibility Guidelines. W3C publishes them. WCAG 2.2 groups its guidance under four ideas:

  • Perceivable: people can get the information, including text alternatives for pictures.
  • Operable: people can use the controls, including with a keyboard.
  • Understandable: labels, instructions and navigation make sense.
  • Robust: the HTML works with browsers and assistive technology.

There are A, AA and AAA levels. AA includes A requirements and is a common target. This lesson introduces a few checks; it does not certify the whole site as compliant.

1. Describe useful images

<img src="images/little-house.png"
     alt="A small blue house with a yellow door">

Describe what matters in context. Use alt="" for a decoration that adds no information, like the browser icon repeated at the top of these pages. This relates to WCAG 1.1.1, Non-text Content.

2. Use headings and clear link names

<h1>Recipe notebook</h1>
<h2>Breakfast</h2>
<p><a href="toast.html">Read the toast recipe</a></p>

“Read the toast recipe” explains the destination better than “click here.” Do not skip heading levels just to get smaller text. Headings communicate relationships (1.3.1), and link text should explain its purpose in context (2.4.4).

3. Keep text readable

For WCAG AA, ordinary text needs at least 4.5:1 contrast against its background. Large text needs at least 3:1. Large means at least 18 points, or 14 points when bold—roughly 24px, or 18.7px bold. These are contrast ratios, not font-size rules for all text.

Use a contrast checker rather than guessing. Also try browser zoom at 200%. Text should remain available without being cut off. Keep links underlined so colour is not their only sign.

4. Try the keyboard

  1. Press Tab to move between links and controls.
  2. Press Shift + Tab to move backwards.
  3. Press Enter to follow a focused link.
  4. Check that you can see which item has focus.
a:focus {
    outline: 3px solid navy;
}

Do not remove the focus outline. Keyboard access relates to 2.1.1; a visible focus indicator relates to 2.4.7. The “Skip to page content” link on this site lets a keyboard user pass the repeated menu (2.4.1).

5. Give an input a label

<label for="visitor-name">Your name</label>
<input type="text" id="visitor-name" name="visitor-name">


Practice only. This field does not send or save anything. Click the label to focus the field.

The label's for value must match the input's id. A placeholder alone is not a replacement for a label. See 1.3.1 and 3.3.2.

6. Let people control media

Do not autoplay sound or add flashing effects. Video with meaningful audio needs checked captions (1.2.2). Important visual information may also need audio description at AA (1.2.5). A written description is useful, but it does not automatically meet all of those requirements.

The sample commercial has no supplied captions. That remains a limitation of the media example. The video lesson and its exercise are also available as text.

Try it

Use only Tab and Enter to visit a lesson. Zoom the page to 200%. Click the “Your name” label above.

Check: You can see focus, reach the links, read the enlarged text and move focus into the matching input.

If it goes wrong

A page can look readable and still have keyboard or screen-reader problems. A checklist or an automatic scan is only part of testing.

References: WCAG 2.2 Quick Reference and W3C Easy Checks.
